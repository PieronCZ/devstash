**Rate Limiting for Auth** (2026-07-13) - Upstash Redis + `@upstash/ratelimit` sliding-window limiting on the auth surface (addresses the deferred L1 finding). New `src/lib/rate-limit.ts`: a module-level `Redis` client (null when `UPSTASH_REDIS_REST_URL`/`TOKEN` are unset → every limiter null), five per-endpoint limiters (`login` 5/15m, `register` 3/1h, `forgotPassword` 3/1h, `resetPassword` 5/15m, `resendVerification` 3/15m), `checkRateLimit()` returning `{ success, remaining, reset }` and **failing open** on a null/broken client or any thrown error (an outage never blocks auth), `ipFromHeaders`/`getClientIp` (leftmost `x-forwarded-for` → `x-real-ip` → `"unknown"`), `retryAfterSeconds()`, and `rateLimitResponse()` (429 with `Retry-After` header + `{ error, retryAfter }` JSON). The four API routes (`register` IP, `forgot-password` IP, `reset-password` IP, `resend-verification` IP+email) check at the top and 429 past the limit. **Login** is limited inside the NextAuth `authorize` callback (keyed IP+email, checked before the DB/bcrypt) — since NextAuth can't emit a 429, it throws a `RateLimitError extends CredentialsSignin` whose `code` embeds the exact wait (`rate_limited_<seconds>`); `SignInForm` parses it. New shared `formatRetryAfter()` in `src/lib/format.ts` (client-safe, so no server-only import leaks into the form) renders precise waits ("9 minutes 51 seconds") for both the API bodies and the sign-in error. Per user: **inline** error display (reusing each form's existing `role="alert"` area) rather than adding a toast lib; the four fetch-based forms already surface `data.error` so only `SignInForm` changed. Documented `UPSTASH_REDIS_REST_URL`/`TOKEN` in `.env.example`. Verified live (Upstash creds present in this env, so real limiting — not just fail-open): register tripped at exactly 3 (429 + `Retry-After: 591` + "9 minutes 51 seconds"), reset-password at exactly 5, and the login callback emitted `code=rate_limited_610` on the 6th attempt (round-trips through NextAuth intact); test users pruned, DB left clean. `tsc`/lint/production build pass. **Known limits:** IP keys trust the leftmost `x-forwarded-for` (safe on Vercel; off a trusted proxy a rotating XFF bypasses IP limits — future defense-in-depth: an email-only secondary limiter on login/resend); the login limiter counts successful attempts too (generous threshold). No DB migration.
